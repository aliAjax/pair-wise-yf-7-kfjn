# 活字排版工坊

一个纯前端本地应用，用来维护字模库、在网格版面中落字，并把**字模库、版面、草稿接成同一本占用账**。

直接打开 `index.html` 即可使用，也可以在本目录启动静态服务访问。

## 占用账规则

- 字模是实物，一种字只有登记的那么多枚。账本分两层：
  - **已存草稿**：点“保存草稿”成功后，这份草稿的落字才占住名额；多份草稿的占用相加。
  - **当前版面（待存）**：未落字的版面按标签页隔离（`sessionStorage`），只做实时预览，不计入正式占用。
- **保存即核对**：保存时把本份草稿的落字加到既有草稿占用上，任一型号超过登记数量则保存停下，横幅明确列出缺哪几个字、各缺几枚（如“山（宋体旧字）缺1枚、月缺2枚”），这次占用不留在账上。
- **数量变更即时重算**：字模卡上的 `−/＋` 调整登记数量后，所有草稿的占用立即重新合计；数量下调造成的缺口会在徽标与账目中标出，落字不删。
- **字模移走先腾空、不丢落字**：删除字模只把它移出字模库，草稿里的落字记录原样保留、不再占名额；重新载入草稿或在当前版面，这些位置以 `◇` 悬空格显示。删除草稿则释放它占的名额。
- **多标签页并发**：共享账（字模库 + 草稿，`localStorage`）按版本号做 CAS 提交——读取最新账 → 应用变更 → 版本号对上才写回；两个标签页同时保存时，后到者自动拿最新占用重算，仍超量则被拒。他页提交通过 `storage` 事件同步，旧版本事件会被忽略。
- **失败可重试、不挂账**：存储写入中途失败（配额、持续冲突）会整体回滚，不产生半截草稿或幽灵占用；候选草稿保留在横幅的“重试保存”里，按当时最新占用重新核对。

## 文件

- `ledger.js`：占用账纯逻辑（占用合计、保存核对、版本号 CAS 原子提交），不依赖 DOM。
- `app.js`：界面与交互，接字模库 / 版面 / 草稿。
- `ledger.test.js`：账本单元测试（含并发写、中途写失败、数量变更、字模移走）。
- `e2e.smoke.js`：用最小 DOM/存储桩模拟两个标签页的端到端流程。

运行测试：

```bash
node ledger.test.js
node e2e.smoke.js
```
